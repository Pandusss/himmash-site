# Сайт НПО «Химмаш»

Новый сайт химмаш24.рф на основе утверждённой дизайн-концепции 01. Два языка (русский и английский), каталог из 14 позиций, сертификаты с переводом, раздел статей для SEO.

Статический сайт на [Astro](https://astro.build): на выходе обычные HTML-файлы, которые можно разместить на любом хостинге, в том числе бесплатно на GitHub Pages.

## Запуск

Нужен Node.js 22.12 или новее.

```bash
npm install
npm run dev      # локально: http://localhost:4321
npm run build    # готовый сайт в папке dist/
npm run preview  # посмотреть собранный dist/
```

## Структура

| Где | Что |
|---|---|
| `src/i18n/ru.ts`, `en.ts` | Все тексты интерфейса и главной страницы. Русский — исходный, у перевода та же структура. |
| `src/data/products.ts` | Список оборудования: адрес страницы, категория, фото, связанные позиции, этапы технологической цепочки. |
| `src/data/products.ru.ts`, `.en.ts` | Тексты, характеристики, цены и условия по каждой позиции. |
| `src/data/documents.ts` | Сертификаты и ТУ: расшифровка и переводы. Сканы — в `public/img/docs/`. |
| `src/data/company.ts` | Телефон, почта, адрес, разметка организации для поисковиков. |
| `src/content/articles/<язык>/<адрес>.md` | Статьи. |
| `src/views/` | Шаблоны страниц. `src/pages/` только связывает адреса с шаблонами. |
| `src/styles/global.css` | Стили утверждённой концепции без изменений; `site.css` — новые блоки. |
| `docs/glossary.md` | Глоссарий терминов для переводов. |

Адреса: русская версия без префикса (`/equipment/centrifuge/`), английская — `/en/…`. Старые адреса китайской версии `/zh/…` перенаправляют на английские страницы.

## Как добавить статью

1. Создайте `src/content/articles/ru/<адрес-латиницей>.md`:

   ```markdown
   ---
   title: "Заголовок до 70 символов"
   description: "Описание для поисковиков, 140–170 символов"
   date: 2026-10-15
   cover: "img/products/08-01-1200.webp"
   coverAlt: "Что изображено на фото"
   products: ["friction-washer", "centrifuge"]
   ---

   Текст статьи в Markdown. Разделы — через ##.
   ```

2. Перевод кладите с тем же именем файла в `en/`. Если перевода нет, статья просто не появится в английской версии.
3. Ссылки на оборудование внутри статьи — относительные: `[центрифуга](../../equipment/centrifuge/)`. Они работают во всех языках.
4. Черновик можно скрыть строкой `draft: true`.

## Форма заявки

Пока адрес обработчика не задан, форма ничего не собирает и не хранит: она открывает почтовую программу посетителя с готовым письмом на ggg13@yandex.ru. Приложить файлы в таком режиме нельзя, поэтому форма напоминает приложить их к письму вручную.

Поля (`src/components/InquiryDialog.astro`, тексты в `form` словарей `src/i18n`): `name`* и `phone`*, `company`, `email`; `need`* (что нужно), `feedstock`, `volume`, `message`, `files[]` (до 3 файлов по 10 МБ); `consent`* с `consent_version` и `consent_at`; служебные `subject`, `page`, `lang`. Кнопка с `data-need` заранее выбирает вариант «Что нужно» (на страницах оборудования — по типу товара).

Для боевого сайта нужен обработчик, который принимает заявку (FormData) и отправляет письмо. Его адрес задаётся переменной `PUBLIC_FORM_ENDPOINT`, см. `.env.example`. Форма собирает персональные данные, поэтому по ч. 5 ст. 18 152-ФЗ обработчик должен работать на сервере в России — например, PHP-скрипт на российском хостинге, как `api/send-form.php` на текущем сайте. Зарубежные сервисы форм (Formspree, Web3Forms и подобные) не подходят. Перед запуском также нужны политика обработки персональных данных и отдельное согласие на обработку у формы.

## Публикация

`.github/workflows/deploy.yml` собирает сайт и публикует его на GitHub Pages при каждом изменении ветки `main`.

В настройках репозитория (Settings → Secrets and variables → Actions → Variables) задайте:

- `SITE_URL` и `BASE_PATH`: для превью `https://<user>.github.io` и `/<repo>/`;
- `PUBLIC_NOINDEX=true` для превью, чтобы копия не попала в поиск и не конкурировала с основным доменом;
- `PUBLIC_FORM_ENDPOINT`, когда будет готов обработчик формы.

В Settings → Pages выберите источник GitHub Actions.

Превью: https://pandusss.github.io/himmash-site/ (закрыто от индексации). Оно собирается одним сайтом: русский в корне, английский в `/en/`.

### Два домена: русский .ru и английский .com

Боевой сайт — два отдельных сайта: русский на домене .ru, английский на .com, каждый в корне своего домена. Переключатель языка и `hreflang` ведут на тот же раздел другого домена; `x-default` — английский сайт. У каждого домена свои `sitemap.xml` и `robots.txt`. Старые адреса `prod01.html…prod14.html` есть только на русском сайте.

```sh
PUBLIC_SITE_URL_RU=https://<домен>.ru PUBLIC_SITE_URL_EN=https://<домен>.com npm run build:sites
```

Результат: `dist-ru/` для домена .ru и `dist-en/` для .com, каждый сразу проверен `scripts/check-dist.mjs`. Адреса можно записать в `.env`. Одну сборку делает `npm run build:sites -- en`; внутри это `astro build` с `PUBLIC_SITE_LANG=ru|en` (см. `src/i18n/index.ts`). Домен в тексте политики и согласия подставляется из этих же адресов. Старый домен химмаш24.рф стоит оставить и перенаправить (301) на новый .ru, чтобы не потерять его историю в Яндексе.

## Аналитика

Русский сайт — Яндекс Метрика, английский — Google Analytics 4 (`src/data/analytics.ts`). Включаются переменными при сборке:

- `PUBLIC_YANDEX_METRIKA_ID` — номер счётчика Метрики (только цифры);
- `PUBLIC_GA_ID` — идентификатор потока GA4 вида `G-XXXXXXX`;
- `PUBLIC_YANDEX_VERIFICATION`, `PUBLIC_GOOGLE_VERIFICATION` — значения `content` мета-тегов подтверждения для Вебмастера и Search Console.

Без ID ничего не загружается и баннера нет. С ID внизу появляется уведомление о cookie: счётчик загружается только после «Принять», выбор хранится в браузере, ссылка «Настройки cookie» в подвале спрашивает снова; при отказе cookie счётчика удаляются. Вебвизор в Метрике выключен (он записывал бы ввод в форму). В политике обработки данных разделы про cookie и аналитику появляются сами, когда счётчик подключён (`analytics` в `src/data/legal.ts`).

Цели (в Метрике — «JavaScript-событие» с этим идентификатором, в GA4 — событие): `inquiry_open` — открыта форма, `inquiry_sent` — заявка отправлена, `phone_click`, `email_click`, `messenger_click` — нажатие на телефон, почту, MAX.

## SEO

- У каждой страницы и каждого языка свой адрес, `title`, `description`, `canonical` и `hreflang`.
- `sitemap-index.xml` и `robots.txt` собираются автоматически.
- Разметка schema.org: организация, хлебные крошки, товары (с ценой, где она указана), статьи, частые вопросы.
- После переезда добавьте русский сайт в Яндекс Вебмастер, английский — в Google Search Console (русский можно и туда), и отправьте sitemap каждого. Старые адреса `prod01.html…prod14.html` уже ведут на новые страницы оборудования (соответствие — поле `original` в `src/data/products.ts`).
